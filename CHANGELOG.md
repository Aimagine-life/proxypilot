## [0.16.7] — 2026-08-28

### Исправлено
- **NotebookLM перестал открываться через прокси.** В июле 2026 Google
  переименовал сервис в Gemini Notebook и переехал: `notebooklm.google.com`
  теперь отдаёт 302 на `notebook.google.com`, лендинг `notebooklm.google` — на
  `notebook.google`. В пресете был только старый хост, поэтому редирект выпадал
  из маршрутизации и уходил напрямую с реального IP — и сервис снова упирался в
  гео-блок. Пресет теперь покрывает все четыре домена; у уже установленных
  расширений новые домены дописываются в пресет при обновлении, выбор сервисов
  не сбрасывается. Название пресета оставлено прежним — по нему сервис ищут.

> Store changelog (EN): Fixed — NotebookLM (now Gemini Notebook) stopped working
> through the proxy: Google moved the app from notebooklm.google.com to
> notebook.google.com (and the landing page from notebooklm.google to
> notebook.google), so the redirect fell outside the preset and went direct from
> your real IP. The preset now covers all four hosts; existing installs get the
> new domains on update without losing their selected services.

## [0.16.6] — 2026-07-16

### Исправлено
- **PAC-скрипт роутил домены-двойники.** `dnsDomainIs` в браузерах — простое
  сравнение суффикса строки: `fakegoogle.com` подпадал под правило `google.com`
  и уходил через прокси (для бесплатного пула — через недоверенный), хотя иконка
  показывала «напрямую». Теперь PAC проверяет границу домена точно так же, как
  логика иконки: сам домен или его поддомены — и ничего больше.
- **Результат автоопределения протокола («Найден HTTP/SOCKS5…») пропадал мгновенно**
  из-за перерисовки настроек поверх него; а устаревший результат старой проверки
  мог всплывать при следующих открытиях попапа. Показ привязан к живому переходу
  «идёт проверка → готово».
- **Выключенное расширение больше не вмешивается в настройки прокси.** Если
  расширение выключено, а в системе сбоит чужой/системный прокси, обработчик
  ошибок мог запустить скан бесплатного пула и временно перехватывать
  chrome.proxy.settings. Теперь при выключенном расширении ротация не запускается.
- **Попап не «застревает» на невыбранном источнике.** Вкладка источника
  переключается мгновенно (оптимистично); если фон упал с ошибкой до сохранения,
  попап теперь перечитывает реальное состояние из хранилища вместо показа
  вкладки, которая на самом деле не активна.
- **Главный экран обновляется вживую.** Фоновая ротация прокси или RKN-проверка
  при открытом попапе теперь сразу отражаются на главном экране (статус, пресеты,
  баннеры). Экран настроек намеренно не перерисовывается — там редактируемые поля.
- **Тест прокси/сервиса всегда показывает результат.** При неожиданном исключении
  в фоновом процессе ответ раньше терялся и карточка результата молча не
  появлялась — теперь приходит честная ошибка.
- **Ошибка «все источники недоступны» локализована.** Раньше русский текст
  попадал внутрь англоязычного сообщения об ошибке загрузки списка прокси.
- Мелкое: некорректный символ `%` в пароле proxy-URL больше не роняет разбор
  строки; тест прокси не падает, если фоновый процесс не успел ответить; битая
  запись пресета в хранилище больше не может уронить загрузку состояния;
  конкурентные проверки РКН-реестра не скачивают 18-МБ список дважды; свежесть
  warm-standby прокси (`validatedAt`) фиксируется в момент проверки, а не в конце
  скана.

> Store changelog (EN): Fixed — PAC no longer routes lookalike domains
> (`fakegoogle.com` matched `google.com` due to dnsDomainIs suffix matching);
> scheme auto-detect result no longer disappears instantly or reappears stale on
> later popup opens; a disabled extension no longer touches proxy settings when
> an external proxy fails; the popup resyncs to the real proxy source if
> switching fails mid-way; the main screen updates live while the popup is open;
> proxy/service tests always report a result; "all sources unavailable" error is
> now properly localized.

## [0.16.5] — 2026-07-16

### Исправлено
- **«Проверить прокси» больше не отключает прокси.** После любого теста прокси
  (а также автоопределения протокола) расширение временно подменяло PAC-скрипт и
  затем сбрасывало настройки, но из-за кэша «PAC не изменился» не применяло их
  обратно — браузер оставался вообще без прокси до ближайшего перезапуска
  service worker'а, и трафик шёл с реального IP при зелёном статусе. Теперь
  рабочий PAC восстанавливается сразу после теста.
- **Предупреждение, когда настройками прокси управляет не ProxyPilot.** Chrome
  отдаёт контроль над прокси тому расширению, что установлено позже; проигравший
  `set()` молча игнорируется — ProxyPilot думал, что всё применил, показывал
  зелёный статус, а трафик шёл напрямую (казалось «прокси подключен, но регион
  RU»; временно лечилось переустановкой). Теперь расширение проверяет
  `levelOfControl` и честно сообщает: янтарный баннер на главном экране и в
  настройках, явная ошибка вместо бессмысленного результата в «Проверить прокси»
  и автоопределении протокола. Отдельное сообщение для блокировки системной
  политикой (антивирус / корпоративная политика). Спасибо Георгию за баг-репорт.

> Store changelog (EN): Fixed — testing the proxy no longer silently disables it
> (the routing PAC is restored right after each probe; previously traffic could
> bypass the proxy with your real IP until the service worker restarted). Added —
> ProxyPilot now detects when another extension or a system policy controls
> Chrome's proxy settings and shows a clear warning instead of a false green
> status. Thanks to a user bug report.

## [0.16.4] — 2026-07-01

### Исправлено
- **Понятное сообщение о SOCKS-прокси с паролем в Chrome.** Chrome не умеет
  передавать логин/пароль SOCKS-прокси — это ограничение самого браузера: в его
  API нет поля для этого, а событие авторизации (`onAuthRequired`) для SOCKS не
  срабатывает. Раньше пароль молча игнорировался, и подключение падало с невнятным
  «failed to fetch». Теперь расширение честно предупреждает об этом в форме под полем
  авторизации и в результате проверки прокси — и подсказывает рабочие варианты: убрать
  пароль и ограничить доступ по IP, выбрать HTTP/HTTPS или использовать ProxyPilot для
  Firefox (там SOCKS с паролем работает). «Свой пул» больше не помечает такой прокси
  «мёртвым» и не запускает бесполезную ротацию. Спасибо
  [@vasyna](https://github.com/vasyna) за баг-репорт (#9).

> Store changelog (EN): Fixed — clearer handling of password-protected SOCKS proxies
> in Chrome. Chrome structurally can't send credentials to SOCKS proxies (a browser
> limitation), so the password was silently dropped and the connection failed with a
> cryptic "failed to fetch". ProxyPilot now warns about this in the settings form and the
> proxy test, and suggests working alternatives — allow access by IP, use HTTP/HTTPS, or
> ProxyPilot for Firefox (where SOCKS auth works). Thanks @vasyna (#9).

## [0.16.3] — 2026-06-24

### Исправлено
- **Пресет восстанавливается, когда домен выходит из реестра РКН.** Раньше, если
  домен сервиса попадал в реестр РКН, расширение выключало его пресет — но когда
  домен из реестра убирали, пресет так и оставался выключенным (приходилось
  включать вручную). Это, в частности, касалось YouTube. Теперь расширение
  запоминает, что выключило пресет именно из-за РКН, и само включает его обратно,
  когда блокировка снимается. Пресеты, выключенные пользователем вручную, не трогаются.

> Store changelog (EN): Fixed — a preset auto-disabled because its domain entered
> the RKN registry is now restored automatically once the domain leaves the
> registry (affected YouTube). User-disabled presets are left untouched.

## [0.14.1] — 2026-06-18

### Исправлено
- **Бесплатный прокси: стабильнее первое подключение.** Раньше первый заход на
  новый сайт через медленный бесплатный прокси мог не открыться, а расширение
  тут же начинало перебирать прокси — приходилось ждать и перезагружать. Теперь:
  - при подборе **отметаются медленные** прокси: берётся быстрый (отклик ≤ 1.5 с),
    а если все медленные — самый быстрый из проверенных, а не первый попавшийся;
  - прокси больше не считается мёртвым после **одной** ошибки — ротация только
    при повторных сбоях (3 за 15 с), поэтому разовый медленный коннект
    переживается без смены прокси;
  - PAC-настройки прокси больше **не переустанавливаются вхолостую** (при
    изменениях состояния, не связанных с прокси) — лишняя переустановка рвала
    активные соединения; теперь применяется только при реальном изменении
    конфигурации;
  - **тёплый запас прокси.** Рабочие прокси, оказавшиеся медленнее выбранного,
    сохраняются как запас — при смене прокси переключение на уже проверенный
    происходит мгновенно, без долгого перебора.

## [0.9.0] — 2026-06-10

### Добавлено
- **«Свой пул» — третий источник прокси** (Источник: Свой · Свой пул · Бесплатный).
  Вставь список своих прокси (по строке: `socks5://user:pass@host:port`,
  `http://host:port`, `host:port:user:pass`) — плагин подключит первый, а если он
  перестанет отвечать, **сам переключится на следующий** из твоего списка (мёртвый
  помечается на 30 мин, как в бесплатном пуле). Это решение проблемы дохлых
  бесплатных прокси: свой пул доверенных адресов с авто-ротацией.
  - Переиспользует механику ротации/пометки мёртвых; источник — твой список.
  - Выбор оптимистичный, без предварительной валидации: приватные прокси с auth
    проверяются по факту работы (`onAuthRequired` по `state.proxy`), а текущий
    можно проверить кнопкой «Проверить прокси». Кнопка «↻ Следующий» — вручную.

## [0.5.1] — 2026-05-28

### Исправлено
- Бесплатный пул больше не падает с `no working proxies found (tried 10)`
  на первой же попытке. Корень проблемы — Proxifly в `/all/data.json`
  держит в топе записи с `anonymity: transparent`, `country: ZZ`,
  `score: 1`. Такие прокси либо палят IP, либо мёртвые, либо мгновенно
  банятся Google.
- Cloudflare CDN trace, через который раньше проверяли живость, отвергает
  большинство free-IP с HTTP 403 — это L7-блаклист CF.

### Изменено
- Health-check переключён на `https://www.google.com/generate_204` —
  endpoint, спроектированный именно под connectivity checks (Android
  бьёт его миллиарды раз в сутки), без rate-limit, без тела для парсинга.
  Бонус: прокси, прошедший этот тест, с большой вероятностью пройдёт и
  `gemini.google.com`.
- `filterPool` отсекает `anonymity === 'transparent'` и `country === 'ZZ'`.
- Кандидаты сортируются по `score` DESC после shuffle — топ-качество
  вперёд, при равенстве остаётся случайность.
- Validate timeout: 3 s → 5 s (free-прокси часто отвечают 5–10 s).
- Попыток на проход: 10 → 15.
- `validateProxy` возвращает `{ ok, latencyMs, error }` — country теперь
  берётся напрямую из `candidate.country` Proxifly, парсера CF trace
  больше нет.

  плейсхолдеры, баннеры (AI-предупреждение, RKN), статусы (`Активно`,
  `Выключено`), сообщения тестов и автодетекта, тосты, ошибки добавления

## [0.5.0] — 2026-05-28

Крупный релиз: добавлен альтернативный источник прокси —
[Proxifly](https://github.com/proxifly/free-proxy-list).

### Добавлено
- **Free pool** — режим где плагин сам подбирает рабочий прокси из
  общедоступного списка Proxifly. Включается в настройках pill-группой
  `Источник: Свой | Бесплатный пул`.
- Lazy-валидация: список тянется по триггеру (включение режима, кнопка
  `↻ Сменить`, ошибка прокси), кандидаты проверяются последовательно
  до первого живого.
- Авто-ротация при ошибках: `chrome.webRequest.onErrorOccurred` ловит
  `net::ERR_PROXY_*` / `ERR_SOCKS_*` / `ERR_TUNNEL_*` и автоматически
  переключается на следующего живого. Дебаунс 10 с + флаг
  `rotationInProgress` против гонок.
- Чёрный список стран `RU / BY / CN / IR` (бесполезны для Gemini),
  TTL мёртвых хостов 30 минут.
- Жёлтый баннер на главном экране при `Free pool + любой AI-пресет`:
  «Google может пометить аккаунт» — для типового кейса с Google-логином
  free-прокси настоятельно не рекомендуются.
- Сохранение `manualProxy` отдельно от активного `state.proxy`, чтобы
  переключение `Свой ↔ Бесплатный` не теряло введённые юзером значения.

### Изменено
- Схема стейта `v1 → v2`. Миграция:
  - `proxy → manualProxy` (копия),
  - `proxySource = 'manual'`,
  - инициализируется `freeProxy { selected, lastError, deadHosts, poolFetchedAt }`.
- Миграция идемпотентна, повторный `loadState` на v1-стейте всё ещё
  возвращает валидный v2.
- Кэш списка прокси трёхуровневый (memory → `chrome.storage` → сеть),
  TTL 5 минут — соответствует частоте обновления Proxifly.

### Технически
- Новый модуль `extension/lib/free-pool.js`: `fetchPool`, `filterPool`,
  `validateProxy`, `pickAndValidate`.
- Новые message handlers в background: `SWITCH_SOURCE`, `ROTATE_FREE`.
  `PERSIST_MANUAL` был запланирован но удалён — popup пишет
  `state.manualProxy` локально через `mirrorManual()`.
- Тесты: free-pool 17, storage migration 11, всего 83.
