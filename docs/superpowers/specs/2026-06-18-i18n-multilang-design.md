# ProxyPilot — Мультиязычность (i18n)

**Дата:** 2026-06-18
**Статус:** Черновик, ожидает ревью пользователя
**Затрагивает:** `extension/` (Chrome MV3 + Firefox сборка), Chrome Web Store, Firefox Add-ons (AMO)

---

## 1. Цель

Сделать интерфейс расширения ProxyPilot мультиязычным. На старте — **русский (RU)** и **английский (EN)**. Язык определяется **автоматически по UI-языку браузера**, без ручного переключателя. Архитектура должна делать добавление будущих языков тривиальным: новый язык = одна новая папка `_locales/<lang>/messages.json`, **ноль изменений в коде и сборке**.

Сейчас весь интерфейс жёстко на русском (~100–120 UI-строк), инфраструктуры i18n нет.

## 2. Решения брейнсторма

| Вопрос | Решение |
|---|---|
| Набор языков на старте | RU + EN |
| Способ выбора языка | Авто по UI-языку браузера, без ручного переключателя |
| Механизм i18n | Нативный `chrome.i18n` + `_locales/` (стандарт WebExtensions) |
| `default_locale` (fallback для непокрытых языков) | `en` |
| Охват первого захода | Весь UI сразу (все 4 экрана + статусы + ошибки + манифест) |
| Английский перевод | Делаю я при реализации, пользователь сверяет |
| Цель | Международный выход в Chrome Web Store и Firefox Add-ons |

## 3. Почему нативный `chrome.i18n`, а не самописный рантайм

- **Автоопределение языка встроено** — ровно то, что мы выбрали («авто по браузеру»).
- **Кросс-браузерность бесплатно** — `_locales` и `chrome.i18n` это стандарт WebExtensions, идентичный в Chrome и Firefox. Самописный слой пришлось бы кросс-браузерно отлаживать вручную.
- **Локализует и манифест** — `name`/`description` в Chrome Web Store и Firefox AMO.
- **Масштабируемость** — добавить язык = одна папка, без правок кода.

Самописный рантайм-слой был бы оправдан только ради ручного переключателя языка — а его мы решили не делать.

## 4. Как работает автоопределение языка (каскад фолбэка)

Браузер подбирает локаль так:

1. Берёт UI-язык браузера (`chrome.i18n.getUILanguage()`).
2. Ищет точную папку в `_locales/` (`de`, `fr`, `zh_CN`…).
3. Для языка с регионом сначала пробует регион, потом базовый: `en_GB` → `en`, `pt_BR` → `pt`.
4. Если совпадения нет — берёт `default_locale` (`en`).

Поведение при наличии только `ru` и `en`:

| UI-язык браузера | Результат |
|---|---|
| ru | русский |
| en, en-US, en-GB | английский |
| de / fr / zh / любой другой | **английский** (fallback на `default_locale = en`) |

Язык интерфейса завязан на язык **самого браузера** (Chrome/Firefox UI), а не на список языков сайтов. Это штатное поведение `chrome.i18n` и нас устраивает.

## 5. Архитектура

```
extension/
  _locales/
    en/messages.json    ← default_locale; fallback для всех непокрытых языков
    ru/messages.json
  lib/
    compat.js           ← без изменений; импорт ПЕРЕД i18n.js
    i18n.js             ← НОВЫЙ: t(), localizeDom(), plural()
    presets.js          ← CATEGORIES: label → labelKey
    domain.js, proxy-backend.js, free-pool.js, icon.js  ← литералы → t('key')
  popup/
    popup.html          ← статичные строки размечены data-i18n атрибутами
    popup.js            ← литералы → t('key', subs)
  background.js         ← литералы → t('key', subs)
  manifest.json         ← name/description → __MSG__, + default_locale: "en"
```

Порядок импорта в каждой точке входа (popup, background): `compat.js` → `i18n.js` → остальное. Это критично: в Firefox `compat.js` переназначает `chrome → browser`, и `i18n.js` должен видеть уже корректный `chrome.i18n`.

## 6. Компонент `lib/i18n.js` (новый, ~50 строк)

Тонкий слой поверх `chrome.i18n`:

- **`t(key, subs?)`** — обёртка над `chrome.i18n.getMessage(key, subs)`. `subs` — строка или массив для плейсхолдеров `$1`, `$2`.
- **`localizeDom(root = document)`** — один проход по DOM, подставляет переводы по атрибутам:
  - `data-i18n="key"` → `textContent`
  - `data-i18n-placeholder="key"` → атрибут `placeholder`
  - `data-i18n-title="key"` → атрибут `title`
  - Также выставляет `document.documentElement.lang = chrome.i18n.getUILanguage()`.
  - Вызывается один раз при загрузке popup.
- **`plural(baseKey, n, subs?)`** — выбирает ключ по CLDR-форме числа `n` (см. §9).

**Почему DOM-проход, а не `__MSG__` в HTML:** браузеры подставляют `__MSG__` только в CSS и манифесте; в HTML — **нет**. Декларативные `data-i18n` + один `localizeDom()` при старте — чистое и масштабируемое решение.

## 7. Словарь `_locales/<lang>/messages.json`

Формат каждого ключа — со `description` для переводчика (и `placeholders`, где нужны подстановки):

```json
{
  "main_services_label": {
    "message": "Сервисы",
    "description": "Заголовок секции со списком сервисов на главном экране"
  },
  "free_progress_text": {
    "message": "Проверено $checked$ из $total$ · $host$",
    "description": "Прогресс подбора бесплатного прокси",
    "placeholders": {
      "checked": { "content": "$1" },
      "total":   { "content": "$2" },
      "host":    { "content": "$3" }
    }
  }
}
```

### Соглашение об именовании ключей

Группировка по экранам/областям — чтобы переводчику было легко ориентироваться:

| Префикс | Область |
|---|---|
| `app*` | `appName`, `appDesc` — манифест (Store/AMO) |
| `main_*` | Главный экран (статус, сервисы, свои домены, баннеры) |
| `settings_*` | Экран настроек (источник, протокол, хост/порт, авторизация, тема) |
| `firstrun_*` | Экран первого запуска |
| `about_*` | Экран «О разработчике» |
| `cat_*` | Категории сервисов (`cat_aiChat`, `cat_video`…) |
| `err_*` | Ошибки валидации (домен, прокси) |
| `free_*` / `own_*` | Статусы подбора бесплатного / своего пула прокси |

## 8. Категории сервисов

В `lib/presets.js` массив `CATEGORIES` переходит с `label` на `labelKey`:

```js
// было
{ key: 'aiChat', label: 'AI-ассистенты' }
// стало
{ key: 'aiChat', labelKey: 'cat_aiChat' }
```

Popup при рендере группы берёт `t(category.labelKey)`. **Названия брендов** (`PRESET_DEFINITIONS[*].label` — Netflix, Gemini, ChatGPT…) — **не переводятся**, остаются как есть.

## 9. Числа и множественное число

`chrome.i18n` не поддерживает плюрализацию нативно. Гибридный подход:

- **Большинство** строк с числами переформулируются нейтрально через плейсхолдеры — формы не нужны:
  `Проверено $1 из $2`, `$1 мин назад`, `$1 прокси распознано`. Английские эквиваленты (`Checked $1 of $2`, `$1 min ago`) формально тоже допускают «1 proxies», но для технического статус-текста это приемлемо.
- **Реально склоняемые** ключевые строки (где «1 прокси / 5 прокси» режет глаз) — через `plural()` с CLDR-формами. Соглашение: ключи `<base>_one`, `<base>_few`, `<base>_many`, `<base>_other`. Для EN используются `_one`/`_other`, для RU — `_one`/`_few`/`_many`. `plural()` сам выбирает форму по `n`.

Точный список «склоняемых» строк фиксируется на этапе плана (ожидается 2–4 штуки), остальные числовые строки идут как простые плейсхолдеры.

## 10. Манифест и сборка

- `manifest.json`:
  - `"name": "__MSG_appName__"`
  - `"description": "__MSG_appDesc__"`
  - добавить `"default_locale": "en"`
- `scripts/build.sh` — **без изменений**. Он зипует всю папку `extension/` (значит `_locales/` попадёт в оба пакета) и делает deep-copy манифеста для Firefox (значит `default_locale` и `__MSG__` сохранятся в Firefox-манифесте автоматически).
- Проверить, что `web-ext lint` для Firefox проходит: он требует `default_locale` при наличии `__MSG__` — у нас он есть.

## 11. Кросс-браузерность (Chrome + Firefox)

- `_locales` и `chrome.i18n` — стандарт WebExtensions, идентичны в обоих браузерах.
- `lib/compat.js` уже переназначает `chrome → browser` в Firefox, поэтому `chrome.i18n.getMessage()` работает в обоих без правок — при условии импорта `compat.js` раньше `i18n.js`.
- Определение языка в Firefox идёт по его UI-локали с тем же фолбэком на `default_locale`.

## 12. Тестирование

- **Новый тест полноты локалей** (`tests/locales.test.js`): множество ключей `en` == `ru` (нет забытых/лишних), и совпадение набора `placeholders` у одинаковых ключей. Это и есть «проще добавлять будущие языки» — добавил язык, тест ловит пропуски/опечатки до релиза.
- Существующие тесты (`tests/domain.test.js`, `tests/compat.test.js`) не должны сломаться.
- Ручная проверка: сменить UI-язык Chrome и Firefox → пройти все 4 экрана (главный, настройки, first-run, about), проверить ошибки валидации и статусы подбора прокси.

## 13. Объём работ (инвентарь источников строк)

| Источник | Что локализуем |
|---|---|
| `popup/popup.html` | Статичная разметка: заголовки, кнопки, баннеры, placeholder'ы, hint'ы (через `data-i18n*`) |
| `popup/popup.js` | Динамика: статусы, ошибки, прогресс, бейджи (~45 строк) |
| `background.js` | Тайтлы/уведомления |
| `lib/free-pool.js` | Статусы подбора прокси |
| `lib/icon.js` | Тайтлы иконки |
| `lib/presets.js` | `CATEGORIES` (8 категорий) |
| `lib/domain.js`, `lib/proxy-backend.js` | Ошибки валидации |
| `manifest.json` | `name`, `description` |

Точная экстракция всех строк в ключи — на этапе плана/реализации. Часть кириллицы в `lib/*.js` — это **комментарии в коде** (не переводятся), их исключаем.

## 15. Вне рамок (YAGNI)

- Ручной переключатель языка в UI (решили не делать — авто по браузеру).
- Языки сверх RU/EN на этом заходе (архитектура готова, но переводы — отдельная задача).
- Локализация README/INSTALL/скриншотов стора (отдельная задача).
- Локализация числовых/датовых форматов сверх описанной плюрализации (`Intl` не требуется для текущих строк).
- Синхронизация выбранного языка между устройствами.
