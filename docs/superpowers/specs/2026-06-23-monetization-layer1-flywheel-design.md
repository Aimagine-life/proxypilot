# Монетизация ProxyPilot — Слой 1: маховик «плагин ↔ канал»

**Дата:** 2026-06-23
**Статус:** дизайн на ревью
**Контекст:** брейншторм монетизации (диалог 2026-06-23). Цель пользователя —
реальный доход; база плагина 500–5k; принцип «простота UI/UX неприкосновенна»
(см. memory `project-simplicity-principle`). Прямая монетизация плагина при такой
базе даёт копейки, а юридически прокси-монетизация (affiliate) токсична для
РФ-резидента (ФЗ 332-ФЗ о рекламе средств обхода, см. ниже). Поэтому выбрана
стратегия «плагин как усилитель уже-монетизированного контент-бизнеса Wildbots»
(YouTube → курсы/услуги). Слой 1 — первый и приоритетный кусок этой стратегии.

## Зачем именно это (опора на данные)

Аналитика источников wildbots-трафика (GA4, ≈27 мая–22 июня 2026, 2 703 новых):

| Источник | Доля | Вывод |
|---|---|---|
| Organic Video (YouTube) | **58%** (1 570) | Доминирующий мотор привлечения |
| Direct | **30%** (804) | Сюда же тонут переходы из расширения (нет UTM, нет referer) |
| Referral | 7% (188) | Внешние ссылки |
| Unassigned | 3,6% (97) | Частично тоже переходы из `chrome-extension://` |
| Organic Search | 1,4% (38) | SEO не задействован (резерв, вне скоупа) |
| Organic Social | 0,2% | Соцсети не задействованы (вне скоупа) |

**Главная проблема, которую решает Слой 1:** вклад плагина в трафик сейчас
**неизмерим** — клики из попапа (футер «Wildbots ↗», экран «О разработчике»)
не имеют UTM и приходят без HTTP-referer, поэтому GA4 относит их к Direct/
Unassigned. Маховик, возможно, уже работает, но его не видно. Нельзя
оптимизировать то, что не измеряется.

## Цель Слоя 1

1. Сделать вклад плагина в трафик на сайт/канал **измеримым** (выделить из Direct).
2. Замкнуть маховик: плагин **деликатно** возвращает пользователя в контент
   (YouTube/гайды), повышая просмотры канала и продвижение по воронке
   курсы→услуги — без ущерба простоте UX.

## Принципы и ограничения (неизменны)

- **Простота превыше всего.** Никаких баннеров/апселла на главном экране.
  Точки возврата живут на экране «О разработчике», где это уместно по контексту.
- **Без слежки в плагине.** Внутри расширения НЕ ставим аналитику/трекеры.
  Измерение — только на принимающей стороне (GA4 сайта) по входящим UTM.
  Privacy-policy и манифест permissions НЕ меняются.
- **Юридическая чистота.** Ссылки ведут на AI-контент/услуги Wildbots
  (разработка ботов, n8n, автоматизация) — это НЕ реклама средства обхода
  блокировок. Тексты не должны связывать продукт с «обходом блокировок».
- **YAGNI.** Никакой телеметрии кликов внутри плагина, никаких контекстных
  «умных» подсказок на старте.

## Компоненты

### 1. UTM-разметка исходящих ссылок плагина

Все ссылки из попапа на ресурсы Wildbots получают UTM-параметры, чтобы GA4
выделял их в отдельный источник.

Затрагиваемые ссылки (по `extension/popup/popup.html`, проверить полный список
при реализации):
- Футер главного экрана: `https://wildbots.ru/` («Wildbots ↗»).
- Экран «О разработчике»: ссылка «🌐 Сайт» → `https://wildbots.ru/`.
- Новая ссылка на канал/гайды (см. компонент 2).

Схема меток (единый стандарт):
- `utm_source=proxypilot`
- `utm_medium=extension`
- `utm_campaign=<точка>` — например `footer`, `about_site`, `about_guides`.

Результат: в GA4 появляется измеримый Referral-источник `proxypilot`, отделённый
от Direct. Видно реальный вклад плагина и какая точка работает.

### 2. Деликатная точка возврата в контент

На экране «О разработчике» (`#screen-about` или эквивалент) — добавить одну
ссылку на YouTube-канал/плейлист гайдов рядом с существующей «🌐 Сайт».
Формулировка нейтральная и полезная, напр. «▶ Гайды на YouTube».

- Один пункт, в семействе существующих `.about-link`. Без новых экранов.
- Главный экран (`#screen-main`) НЕ трогаем — простота.
- Ссылка тоже с UTM (`utm_campaign=about_guides`).

**Решение (2026-06-23):** «Гайды» ведут на **YouTube-канал Wildbots** — он
главный мотор привлечения (58% трафика); цель маховика — наращивать его
просмотры/подписчиков, т.к. канал уже сверху воронки курсы→услуги. Точный URL
канала уточнить при реализации.

### 3. Измерение (на стороне GA4 сайта)

- Убедиться, что GA4 на `wildbots.ru` корректно атрибутирует входящий
  `utm_source=proxypilot` как отдельный Referral.
- KPI Слоя 1:
  - доля/абсолют трафика с `utm_source=proxypilot` (ранее скрыт в Direct);
  - распределение по `utm_campaign` (footer vs about_site vs about_guides) —
    какая точка реально кликается;
  - динамика Organic Video после новых видео (для контент-петли, Слой/отдельно).
- Никаких изменений внутри плагина для измерения — всё на сайте.

## Версия и сборка

- Затрагивает только `extension/popup/popup.html` (URL ссылок) и, возможно,
  `_locales/*/messages.json` (новая строка «Гайды»).
- Бамп версии по правилу проекта (memory `feedback-bump-version`): patch-бамп
  `manifest.json` + `package.json`, запись в `CHANGELOG.md` (RU+EN — memory
  `feedback-store-multilang`).
- Релиз — по обычному процессу (memory `project-proxypilot-release`).

## Вне скоупа (отдельные документы)

- **Слой 2** — B2B-подача (плагин как доказательство экспертизы → услуги
  120–200к). Делается в основном на сайте/в видео, не в плагине.
- **Слой 3** — прямая монетизация плагина: невидимый Pro «Авто-пилот»
  (lifetime-лицензия, биллинг Lemon Squeezy + ЮKassa, развязка MIT через
  закрытый Pro-слой). Только когда вырастет база.
- Усиление SEO/Organic Search и Social — отдельный рост-канал.
- Любая аналитика/телеметрия внутри расширения — запрещена принципом.

## Риски / зависимости

- Политики магазинов (CWS affiliate-policy с 10.06.2025, AMO): UTM-ссылки на
  собственный сайт автора с раскрытием — допустимы; это не affiliate-ссылки
  третьих лиц. Тексты держать нейтральными, без «обхода блокировок».
- Юр-риск РФ (ФЗ 332-ФЗ): ссылки ведут на AI-услуги/контент, не на средства
  обхода → низкий риск. Перед коммерцией Слоёв 2–3 — консультация IT-юриста.
